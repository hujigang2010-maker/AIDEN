# 活动志愿者职能分工 Skill

把「议程 + 人员 + 会议结论」沉淀为可执行的 **PPT 方案 + Excel 分工表**，并支持多轮会议纪要迭代。

## 何时启用

- 用户要做峰会/论坛/发布会的志愿者或工作人员分工
- 需要从大项到小项拆解职责，并覆盖应急预案
- 需要根据讨论会/组长会结论调整人员与流程
- 交付物明确为 PPT + Excel（或二者之一）

## 必需输入（缺则追问）

1. **活动基本信息**：名称、副标题、日期时段、场地
2. **完整议程**：时段、环节名、关键岗位、备注
3. **人员池**：姓名（可含花名）、背景/特长、意向岗位（若有）
4. **指挥链**：总策划是谁；是否设双执行总监（统筹 + 会务）
5. **约束**：关键不可动人员、必须对接的嘉宾/赞助、外部联系人

可选：既有会议纪要、物资清单、晚宴流程、外部沟通群。

## 标准组织架构（默认 7 组）

在总策划之下设双执行总监，再落 7 组。人数可按规模缩放，职责边界保持稳定。

| 代码 | 组别 | 核心职责 |
|------|------|----------|
| A | 统筹协调 | 总指挥+双总监口径、进度、对讲调度、嘉宾邀约/赞助落位 |
| B | 嘉宾接待 | 接送、签到分级、动线、休息室、1V1 VIP |
| C | 会务执行 | 舞台流程、主持对接、圆桌/颁奖、计时、席卡 |
| D | 媒体传播 | 拍摄、直播、合影区、物料露出 |
| E | 技术保障 | PPT 收集/播放、麦/灯光/音视频、微调 |
| F | 后勤保障 | 物资、茶歇、晚宴、车辆、场地后勤 |
| G | 应急机动 | 安保对接、突发、机动补位、敏感处置 |

详细子职责与人数建议见 [references/group-architecture.md](references/group-architecture.md)。

## 分配原则（必须遵守）

1. **意向优先，背景校验**：尊重自报意向；与专业背景冲突时说明并调整。
2. **负载均衡**：C/E 在演讲密集时段最重；B/F 在签到与晚宴最重；避免一人多核心岗。
3. **关键岗双备份**：主持对接、PPT 播放、颁奖、对讲中枢、VIP 接送必须有 A/B 角。
4. **指挥不兼操作**：总策划/执行总监不占一线操作岗（可兼决策与对外）。
5. **会议结论覆盖意向**：组长会/二次会明确调组时，以决议为准并记录原因。
6. **从大到小**：组别 → 子职责 → 时段落位 → 单人当日时间表 → 物资/对接清单。

## 执行流程

### Step 1 — 结构化数据

在仓库中维护（或新建）生成脚本的数据块，至少包含：

- `EVENT_*` / `AGENDA`
- `GROUPS`（含 sub_duties）
- `ASSIGNMENT`（人 → 组 → 主责 → 备注）
- `BACKUP_ROLES`（关键岗 A/B）
- `CONTINGENCIES`（情景 → 处置 → 责任组）
- `MILESTONES`（D-7 / D-3 / D-1 / D-day 节点）
- `OPT_SUGGESTIONS`（建议 + 状态：采纳 / 调整 / 暂缓 + 理由）
- 按需：`EXTERNAL_CONTACTS`、`EXTERNAL_GROUPS`、`BANQUET_FLOW`、`ARRIVAL_TIMES`、`MATERIALS`、`LIAISON_LIST`、`TIME_SOP`、`PHASE_MATRIX`

本仓库参考实现：`build_volunteer_assignment.py`。数据 schema 见 [references/data-schema.md](references/data-schema.md)。

### Step 2 — 人员落位

对每个人输出一行：`姓名 | 组别 | 主责 | 协作 | 当日到场 | 备注`。

圆桌/颁奖/主旨演讲等重环节，建立 **C 组对接矩阵**（环节 → 主对接 → 技术 → 计时）。

### Step 3 — 建议筛选

收到「优化建议」时，逐条标注：

| 状态 | 含义 |
|------|------|
| 采纳 | 已写入分工/SOP/物资 |
| 调整 | 部分采纳，说明改动点 |
| 暂缓 | 本期不做，写清条件或风险 |

禁止只罗列建议不落地；采纳项必须反映到 ASSIGNMENT / MATERIALS / CONTINGENCIES 等数据中。

### Step 4 — 生成交付物

依赖：`python-pptx`、`openpyxl`。

```bash
pip install python-pptx openpyxl -q
python3 build_volunteer_assignment.py
```

交付物清单见 [references/deliverables.md](references/deliverables.md)。

### Step 5 — 会议纪要迭代

每次新纪要：

1. 抽出决议（调组、到场时间、物资、外部对接）
2. 更新数据块 + 版本号（如 v8 → v8.1）
3. 在 PPT 增加「会议结论 / 决议总览」页
4. 重新生成 PPT/Excel，说明相对上一版的变更摘要

## PPT 结构（建议顺序）

1. 封面（活动名为主视觉信号）
2. 指挥架构 / 双执行总监
3. 七组一览 + 各组详页
4. 实际人员分配表
5. 议程 × 责任组矩阵
6. 关键岗 AB 角
7. 应急预案
8. 里程碑与到场时间
9. 外部对接人 / 沟通群
10. 晚宴流程（若有）
11. C 组对接矩阵
12. 建议筛选结果 + 会议决议总览

单页一个目的；避免把统计条、日程碎片塞进封面/首页。

## Excel 工作表（建议）

总览、人员分配、各组详表、议程矩阵、AB角、应急、里程碑、物资、外部对接、沟通群、晚宴、到场时间、对接矩阵、建议筛选、联络表。  
列宽与表头着色按组别色板区分，便于打印。

## 质量检查清单

- [ ] 每人有且仅有一个主组（机动兼职写在备注）
- [ ] 每个议程时段有责任组字母
- [ ] PPT 播放、对讲、颁奖、VIP 接送均有备份
- [ ] 应急覆盖：嘉宾迟到、设备故障、医疗、舆情、天气/交通、人员缺席
- [ ] 物资数量与责任人可追溯到人
- [ ] 建议条状态完整，无「悬空建议」
- [ ] 重新运行生成脚本无报错，文件可打开

## 输出与用户沟通

- 先给结论：架构人数、关键调岗、本版相对上版变化
- 附 PPT/Excel 路径与再生命令
- 不要替用户编造未提供的真实联系方式；占位写「待确认」
